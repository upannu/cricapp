# Master Test Cases

Consolidated, requirement-linked test case master list across all six domains. Built from [`docs/reverse-engineered/test-cases.md`](../reverse-engineered/test-cases.md) (the per-domain source) — reformatted to the required column set (Test Case ID, Requirement ID, Scenario, Preconditions, Test Data, Steps, Expected Result, Test Type, Priority, Risk, Automation Status, Component), with a `Risk` column newly derived from each case's Priority (P0/Critical→HIGH, P1/High→MEDIUM-HIGH, P2/Medium→MEDIUM, P3/Low→LOW — a defensible, disclosed heuristic, not a separately-assessed risk rating), and genuine Requirement-ID linkage added for the three domains (Academy/Admin, Portal/Content, Payments Core) that lacked it in the original pass — see the section header on each for how that linkage was derived.

**Automation Status legend** (per Step 11 of this phase — never claim execution that didn't happen):
- `EXISTING_TEST` — a real, already-committed automated test in this repo covers this exact case (file cited)
- `DESIGNED_TEST` — this test case is fully specified here but has not yet been automated or executed
- Neither label implies PASS/FAIL. No test in this document has been marked PASS or FAIL — only `NOT_EXECUTED` applies to anything not already running in CI, per Step 11's instruction.

Sections 1-3 below (Auth, Player, Marketplace) are reformatted directly from the existing ID-linked source. Sections 4-6 (Academy/Admin, Portal/Content, Payments Core) have newly-added Requirement ID linkage, with the linkage method documented inline at the top of each section. New Security and Negative test cases added for this phase (Steps 7-8) are appended in their own sections at the end, cross-referenced to `test-scenarios.md`.
